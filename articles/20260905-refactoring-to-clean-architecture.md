## 実践前に座学

実際の検証に入る前に、クリーンアーキテクチャとは何なのかを改めて整理したいと思います。理解できている人は読み飛ばして貰って大丈夫です。

### **関心の分離**とは

クリーンアーキテクチャを理解するためにはこの**関心の分離**という考え方を理解する必要があります。
ここを理解できているかできていないかでここから先の理解度が大きく変わると思います。

https://ja.wikipedia.org/wiki/%E9%96%A2%E5%BF%83%E3%81%AE%E5%88%86%E9%9B%A2

> 関心の分離（かんしんのぶんり、英語: separation of concerns、SoC）とは、ソフトウェア工学においては、プログラムを関心（責任・何をしたいのか）毎に分離された構成要素で構築することである。

自分の中の理解としては、「1つのファイルや関数に全てを詰め込むのではなく、ちゃんと役割や機能単位で適切に分けましょうね～」と理解してます。

## クリーンアーキテクチャを段階的に導入する検証

ではいよいよ実践編です。
実際のコードへ段階的にクリーンアーキテクチャを導入して1つ1つ理解していきましょう。

### 課題設定

今回は下記のECサイトの機能を題材に行っていきます。

#### Features

| 機能 | 説明 |
|------|------|
| 商品一覧の取得 | カタログから商品を一覧表示する |
| カートへの追加・削除 | ユーザーが商品をカートに追加・削除する |
| 注文確定 | 在庫チェック → 合計金額計算 → 注文作成 |
| 注文履歴の参照 | 過去の注文を確認する |

#### Domain Rules

- 在庫が不足している場合、注文は確定できない
- 合計金額には消費税（10%）が加算される
- 注文が確定すると在庫が減少する
